# Why the desk stopped placing orders — and what is still open

Written 2026-09-05, at the end of the run that found it. Everything here was
established by reading the code, the git history and the live box; where a
number appears it was measured, and the measurement says so.

---

## The short version

The desk placed orders on **27 August**. It placed none from **1 September**.
Nothing broke. On 31 August a winning backtest was adopted, and the adopt
copied the backtest's **feed** onto the live setup — polygon, which is the
right feed to test a year against and cannot decide this morning's bar. From
the next session every 09:35 decision timed out and printed *MISSED THE 09:35
WINDOW*, which reads as the platform being slow.

That was the cause. Six other faults were found on the way to it, each of
which would have produced the same silence on its own.

---

## The chain, in the order it was found

Each of these was live at the same time. Fixing any one alone would not have
produced an order.

**1 · The setup was on polygon.** Free plan: a day behind, five requests a
minute. Forty symbols cannot finish inside the eighteen seconds a clock setup
has. Both attempts timed out every morning.
→ `src/setups/feeds.js` — polygon, hybrid and hybrid_yahoo are never used
live; a consolidated feed is substituted and the reason is printed on the card.

**2 · Adopt copied the feed.** `src/setups/parity.js` read `feed: bt.feed`.
The fill model three lines below has always been *translated* for exactly this
reason, with a comment saying that copying the backtest's own value "would stop
the desk firing altogether". The feed needed the same rule and nobody had
applied it. A test asserted the feed came across as polygon — it was locking in
the bug.

**3 · qp served every live decision from a frozen cache.** The desk sends
`asof=today` on every call, and qp treated that as a historical replay: the
window ended at tomorrow's midnight, a constant for the whole day, so the first
fetch of a symbol each day was reused until midnight. Found from a phone
screenshot showing yahoo 85 and 90 minutes behind at 15:44.
→ `compare_server.is_live_asof()` — a replay of today is live.

**4 · The Control ran in six processes at once** and saturated qp — four
identical timeouts at the same second. It also had no exit rule, so on quiet
stocks it never fired and reported a false negative.
→ one owning process, never in a minute a real setup decides, and a
deterministic strategy.

**5 · Screener counts saturated at the page size.** Six different filters all
read "97" on a box whose page was 100. A number that was arithmetically correct
about the wrong thing.
→ `totalCount`, not the row count.

**6 · The chart's controls were never wired.** They were attached at the end of
the page's startup, after `await loadSources()`. The chart is drawn before that
and not awaited — so one endpoint that fails or hangs left the chart visible and
every control dead. Reproduced in a real browser: selecting a value changed
nothing, and no preference was ever stored. This had been true of the Scale
control for weeks.
→ controls wired before anything is fetched; every startup await carries its
own catch.

**7 · The docked toolbar was drawn below the fold.** On Android Chrome the body
can be taller than what is visible while the URL bar shows. `<main>` reaches the
bottom of the body, so a rail anchored to it is off-screen. The time axis stayed
readable because a separate correction measures the axis and shortens the chart
— a correction that knew nothing about the rail beneath it, which is why exactly
one of the two was visible.
→ the docked rail is fixed to the viewport, and the axis correction subtracts
its measured height.

## The feed, decided

Three settings, and only one of them decides a trade:

| where | governs |
|---|---|
| qp chart page, `Feed` | that chart, right now |
| Algo → Settings → Data feed | charts and backtests |
| **Algo → setup card → `feed`** | **the live decision** |

The desk's answer, and it is a reversal made during this run:

- **backtest on polygon** — the only feed here with years of 1-minute history.
- **decide live on yahoo** — the only free feed that answers during the session,
  and it reports the **consolidated tape**.
- **alpaca is chosen, never defaulted to.** Its free tier is IEX: measured at
  0.17M shares of AAPL on a morning the consolidated tape carried 4.2M. Both
  live setups stop **at the session VWAP**, which is volume-weighted — so on
  this desk the feed decides where the stop sits. qp already refuses to report a
  VWAP-stopped backtest run on alpaca.

An earlier change in this run made alpaca the default for an unchosen setup, on
the argument that a real-time feed beats a delayed one. That argument ignored
three measurements already written down in the platform, and it was reversed.
The rule that settled it: **a visible skip beats a silent wrong number.** If
yahoo runs late the decision is skipped and logged; a stop drawn from four
percent of the tape is silent, and it trades.

**Polygon-tested against yahoo-live is not a divergence.** Both are the
consolidated tape and agree on VWAP to within 0.06%, so the parity report calls
that pair a match. Alpaca against either stays a divergence, in both directions.
There is nothing to re-run: yahoo cannot serve a backtest (≈1 month of 1-minute
bars, 5 days per request) and is not being asked to.

## What the trader can run

All read-only. None of them changes a screener, a setup or an order.

```
node scripts/check-screeners.js
```
Every enabled screener on every live tool, validated by its own tool and run
once against TradingView. Prints a table and a PROBLEMS list. Knows the market
hours, so a shut market is not reported as a fault.

```
DB_PATH=data/t10.db node scripts/why-empty.js canslim
```
Runs the screener with each filter dropped in turn and names the one that
empties it — or says plainly that no single rule explains it and the
*combination* is what is rare.

```
DB_PATH=data/t10.db node scripts/try-filter.js canslim 4
```
Takes the rule that why-empty named and puts TradingView's counts next to each
alternative. Recommends only what it has seen work in full. Changes nothing.

Rehearse (on the Algo page) runs the whole chain at any minute — cards, filter,
decision, feed, rank, size, routing, order — and places nothing. It exists
because a setup that fires at 09:35 cannot otherwise be tested at 14:00.

### Needs a live session (Monday)

1. **Yahoo's real lag has never been measured on this desk.** The 0/5/5 minutes
   the Control reported were taken while qp was serving from the frozen cache;
   the 85 and 90 minute readings were that bug. The cache is fixed and the
   Control now measures the lag every five minutes. **If yahoo cannot hold two

   against anyone's argument.

   market-wide on its own, and the growth combination around it is also empty —
   two separate decisions. `try-filter.js` puts the counts next to
   `high ≥ price_52_week_high` ("did it *print* a new high today", which is what
   breakout means in every book) and the shorter windows. **The choice changes
   what the screener means, so it is the trader's.**

## The rule this run kept proving

Every failure here was **a silence read as a pass**, or **a number that was
arithmetically correct about the wrong thing**.

- A screener count that saturated at the page size.
- A parity report certifying agreement about a feed nothing was using.
- A check holding a stale copy of the list it was checking.
- A CSS variable that could not resolve, failing silently.
- Tests that asserted the literal text of the broken code — three of them, on
  three different subjects, each passing while the thing it named did not work.

So: an absence is never stored or displayed where an answer belongs; `ok: null`
never counts as a pass; a substring search cannot verify behaviour, only
executing it can. Where this document claims something works, it was run — and
where a fix was added, the test for it was confirmed to **fail** against the
previous file before it was kept.
